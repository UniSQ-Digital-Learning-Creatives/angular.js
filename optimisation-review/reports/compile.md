# compile worker report (templates, link, DOM updates, jqLite)

Working copy: `$S/opt/compile/angular.js`. Patch for SAFE changes: `compile.patch` (src + test, against `opt/base`). BREAKING/optional items are separate patches that apply **on top of** compile.patch: `compile-breaking-lazy-anchorscroll.patch`, `compile-breaking-templaterequest-cache.patch`. Bench pages and tooling: `$S/opt/compile-bench/` (README.md there). Raw A/B output: `compile-bench-results.txt`.

Tests: `MODE=jqlite` 6221/6221, `MODE=jquery` 6226/6226 (baseline 6207/6212, +14 new specs in each mode, no existing spec edited). The two breaking patches also pass the full suite (plus one new spec in the templateRequest one).

Size: angular.min.js 177,243 -> 177,871 bytes (+628), gzip 61,513 -> 61,761 (+248).

Measurement method: the machine is shared and very noisy (same-vs-same runs differ by up to +-10%), so everything below is an interleaved A/B in fresh pages (new tab per sample), median of 7-15 runs, ratio vs the unmodified build of the starting source (`ng/ref.min.js`). Treat ratios inside 0.9-1.1 as noise. Bench pages are built from the real templates (toolbox card grid with ng-include icons and ng-bind-html, media-catalogue gallery, an editor form with every ng-model flavour, the real generator `embed` card/tile themes) with synthetic data; `dirs.html` measures per-directive cost.

## Details of the SAFE changes

**C1 ngInclude cache** (`src/ng/directive/ngInclude.js`, `ngIncludeFillContentDirective`). Cache = `Map` keyed by the template text (so a changed `$templateCache` entry is never served stale), bounded at 100 entries. First inclusion of a template: unchanged path (innerHTML + compile in place, zero extra cost for templates included once, e.g. whole pages). Second inclusion: the freshly parsed nodes are moved into a fragment and compiled once; that and every later inclusion is `linker(scope, clone => $element.append(clone))`. Templates containing `<script` are never cached (jQuery executes inline scripts through `.html()`). The SVG-host WebKit branch is untouched. Suite check: no app directive declares `compile:` (grep of apps), so per-inclusion compile side effects cannot be observed; the `$includeContent*` events and `onload` are unchanged. Specs added: independent scopes/handlers per inclusion, compile count bounded, template change in the cache, switching templates, multi-root/text/comment templates, scripts not cached, more than 100 distinct templates, scope/handler cleanup.

**C2 cleanData**. `jqLite.cleanData` now fires `$destroy` for all nodes first (their data is still readable by the handlers, same two-pass order as the old wrapper in `bindJQuery`, which is now installed only when jQuery is bound), then drops data and the handler lists, and does not call `removeEventListener` for each type. Observable difference: none (a removed element's old native listeners still exist but find an empty handler list; re-adding listeners after a remove works with only the new ones - spec added). Specs added: deep descendants, reuse after removal, `$destroy` ordering.

**C3 inheritedData**: the controller lookups `^?form`, `^?ngModelOptions`, `^ngModel`... of every ngModel walk the whole ancestor chain (about 20 elements deep in the apps); in jqLite mode each step was a full `jqLite.data()` call including a regexp. Specs added for dashed/camelCase names and closest-wins.

**C4** is a 3-line DI change.

## BREAKING / optional items

### B1 lazy `$anchorScroll` in ngInclude (`compile-breaking-lazy-anchorscroll.patch`)
Why: `ngInclude` injects `$anchorScroll`, which instantiates `$location`. That adds `$location`'s `$rootScope.$watch` and the `$anchorScroll` hash watch to every digest, plus URL/popstate/hashchange listeners and a digest on every URL change, on all 25 pages that use ng-include. No ng-include in the suite uses `autoscroll` and no app injects `$location`/`$anchorScroll`/`$route` (grep: no matches).
Gain: 2 fewer root watchers (rootScope.$$watchers.length 2 -> 0), idle digest 5% cheaper (about 5 us per digest, fixed cost, not per watcher).
What changes: `$location` is no longer instantiated by ng-include. Affected pages (those that configure or react to location/hash):
- `toolbox-pronunciation-guide/public/sys/js/main.js:343-349` sets `$locationProvider.html5Mode({enabled:true, requireBase:false, rewriteLinks:false})`; it uses ng-include (`sys/pages/player.html:4,7`, `item-selection.html:8`). With no `$location` there is no html5-mode URL normalisation / popstate digest. The page never reads `$location` and has no hashchange/popstate/location.hash use (grep), so the config becomes inert.
- `si-studydesk-styles/website/sys/js/main.js:365` injects `$locationProvider` but does not configure it; ng-include at `website/index.html:50`. No effect expected.
- `toolbox-reaction-bar/public/dashboard/sys/js/main.js:141,158` reads `location.hash` stripping `#!#`, `!#`, `#!` and listens to `hashchange`. Today `$location` (hashbang mode) rewrites a plain `#foo` hash to `#!foo`-style on load; without it the hash stays as typed. The code strips every variant so it should keep working, but this is the one page to test. It uses ng-include (`sys/pages/summary.html`).
App-side fix if anything breaks: add `.run(['$location', angular.noop])` to that app, or autoscroll users call `$injector.get('$anchorScroll')` themselves.

### B2 `$templateRequest` cache shortcut (`compile-breaking-templaterequest-cache.patch`)
Why: after the first load the template sits in `$templateCache` as a plain string, but each ng-include still runs `$templateRequest` -> `$http.get` (config merge, interceptor chain, promise chain of about 6 promises, cache lookup).
Change: if the cache already holds a string for that url return `$q.resolve(string)`.
Gain: dirs.html c_ngInclude 0.78x (on top of C1), c_ngIncludeDyn 0.88x; embed link-card reload 0.93x, bootCold 0.83x (noisy).
What changes: `$http` request interceptors, `$http.pendingRequests`, `totalPendingRequests` and `$httpBackend` mocks no longer see repeat loads of an already-cached template (the first load is unchanged). Suite: no `interceptors`, `$httpProvider`, `$templateCache`, `pendingRequests`, `$httpBackend` use anywhere in the apps (grep), so nothing is affected; it is listed as BREAKING because it is a visible behaviour change of a core service for third parties.

### Documented, not implemented
- Form-state classes (coordinator item 3): no CSS/JS/HTML in the suite reads ng-valid/invalid/dirty/pristine/touched/untouched/pending/submitted (si-photography-catalogue uses `ng-not-empty` only, which would be kept). Prototype skipping those writes: ngModel create 0.95-0.97x, update 0.78-0.94x (about 1 us per input; noise-level). Not worth a patch; if wanted, a `$compileProvider` opt-out flag (default on) would be the non-breaking way.
- `commentDirectivesEnabled(false)`: no `restrict:'M'` directive and no `<!-- directive: -->` in the apps or in ui-grid (the only third-party Angular lib), so it is safe to flip per app, but the gain is not measurable. `cssClassDirectivesEnabled(false)` would break these 12 class (`restrict:'C'`) directives: toolbox-generators/public/rive-player/sys/js/main.js:34, counter-button-editor/sys/js/main.js:237, horizontal-rule/sys/js/main.js:61, toolbox/public/sys/js/main.js:2352,2374, toolbox-photospheres/public/sys/js/main.js:10, photospheres/public/admin/sys/js/main.js:398, si-photography-catalogue/public/sys/js/main.js:702, toolbox-group-discussion/public/sys/js/main.js:1177,1233,1322, toolbox-suggest-feature/public/sys/js/main.js:156. No `.scope()/.isolateScope()/.injector()` caller and no ng-scope/ng-binding CSS exists in the apps (only comments saying the classes are turned off), so debug info is not needed anywhere.
- Coordinator item 4 (app-side): 80 ng-repeats without `track by` pay `hashKey` and stamp `$$hashKey` on the data objects (visible in `JSON.stringify` of the data); 12 `ilar*` directives with `transclude:true` that never use ng-transclude still clone and link their content once per instance (dirs.html c_transclude: 17-20 us vs 2.6 us plain row).
- `$templateRequest` laziness (coordinator item 2): only `$compile` (templateUrl) and `ngInclude` inject it; ng-include needs `$http` at once, so only pages with neither benefit (C4).

## Where the time goes (profiles)
After C1/C2 the profiles are flat: native `cloneNode` about 10% on churn, scope `$new/$destroy` 10-25% (scope worker's files: `$destroy` self time is the top JS function in ngSwitch/ngInclude/ngIf rows), `(program)` (V8 lazy compile) about 35% of a cold embed boot, `$parse`/`$interpolate` cold parse about 5 of 27 ms of the embed boot (`addAttrInterpolateDirective` 4.8 ms of the 8.4 ms in `collectDirectives`). Script eval of the min.js is about 6.5 ms and is parse cost (build worker); serving the script with cache headers drops it to about 5 ms in Chrome via the code cache (bootstrap unchanged). Select/ngOptions rows cost 40-48 us each (about 25% in `writeSingleValue`/option `selected` property writes, native); ngOptions re-evaluates its watchables for every option on every digest (7% of a typing digest on the 25-select form).
